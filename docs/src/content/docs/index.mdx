Mace—**M**ain **A**pplication **C**onfiguration **E**ngine—is a strongly typed
configuration language. A Mace file declares any reusable types and values in an
optional script block, then exposes exactly one record-shaped data or schema
output.

Mace is designed to make configuration contracts visible to the parser, CLI,
and language server instead of leaving validation and injected values to prose
documentation.

## A minimal data file

```mace
|===|
string first_name = "Shelton";
string last_name = "Louis";
|===|

[output = 'data']
{
  first_name,
  last_name,
  full_name: "$($self.first_name) $($self.last_name)",
}
```

The output fields evaluate from top to bottom. `$self` can read a completed
field, so `full_name` can reuse `first_name` and `last_name` without exposing the
script's private declarations.

## Validate a data output

A schema-output file publishes a contract:

```mace
// package-schema.mace
[output = 'schema']
{
  name: string,
  version: string,
  dependencies: record<string>,
}
```

A data file can load that contract and validate its final output:

```mace
[output = 'data', schema_file = './package-schema.mace']
{
  name: "@example/widget",
  version: "3.0.1",
  dependencies: {
    clsx: "^2.0.0",
  },
}
```

Schemas are closed: required fields must exist, unknown fields are rejected, and
every present value must have the declared type.

## Validate input before using it

```mace
// github-context.mace
[output = 'schema']
{
  branch: string,
  commit: string,
}
```

```mace
[output = 'data', parse_file = './github-context.mace']
{
  workflow: "CI",
  revision: "$($branch)@$($commit)",
}
```

The host supplies a record when evaluating the second file. Mace validates the
entire input first and introduces its fields as `$branch` and `$commit`. Missing
or invalid input stops processing before any output is emitted.

<Aside title="Parsed values are visibly external">

The `$` prefix distinguishes validated host input from ordinary script variables.
It does not bypass type checking.

</Aside>

## Type vocabulary

Mace provides:

- scalar types: `string`, `int`, `float`, `hex_int`, `hex_float`, and `boolean`;
- homogeneous arrays with `array<T>`;
- open homogeneous maps with `record<T>`;
- closed inline records and named `schema` declarations;
- finite literal domains with `choice[...]`;
- explicit alternatives with `variant[...]`;
- compatible record or choice composition with `fusion[...]`.

Optional fields model absence. `null` is not a general runtime value; it is only
an output-field omission marker.

## Deliberate restrictions

Mace keeps configuration predictable by requiring:

- exactly one record-shaped output block;
- at most one script block before the output;
- explicit types and initializers for immutable variables;
- imports before local declarations and no shadowing;
- named imports rather than wildcards;
- closed schemas and explicit variants for mixed values;
- static single-quoted `.mace` source paths;
- complete validation before any result is returned.

Expressions cannot run commands, call arbitrary host functions, mutate state, or
initiate I/O. Only explicit imports and file directives may resolve local or
HTTP(S) Mace sources.
